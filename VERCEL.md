# Ежедневный блок из 15 публикаций в Vercel

Подготовлена Flask-функция `app.py`, маршрут `/api/publish`, и ежедневное расписание
в `vercel.json`: 19:00 UTC = 22:00 по Москве. Один запуск публикует блок из 15
материалов, по три на каждую рубрику. Ежедневный Cron поддерживается Hobby.
Реальная миграция пока не выполнена.

## Переменные Production

- `CRON_SECRET`: случайный секрет длиной не менее 24 символов. Vercel передаёт его
  в заголовке Authorization. Запрос без правильного секрета не вызывает издатель.
- `TELEGRAM_BOT_TOKEN`: токен бота, только как защищённая переменная окружения.
- `JOURNAL_GITHUB_TOKEN`: отдельный fine-grained GitHub token только для
  `make-smart-products/lartdevivre_journal`, с Repository Contents: Read and write.
  Он нужен для сохранения состояния и защиты от дублей. Не переносить широкий
  пользовательский OAuth-токен из системного хранилища учётных данных.
- `JOURNAL_PUBLISH_ENABLED`: изначально `false`. Включать в `true` только после
  проверки production-развёртывания, секретов и права бота публиковать.

Секреты не добавляются в Git. `.vercelignore` исключает локальный `.env`, утилиты
настройки и локальные библиотеки из загружаемого проекта.

## Порядок переключения

1. Подключить Vercel и проверить тариф команды. Не покупать тариф автоматически.
2. Создать проект, связанный с GitHub-репозиторием, настроить защищённые переменные.
3. Развернуть функцию с `JOURNAL_PUBLISH_ENABLED=false`.
4. Проверить `/health`, отклонение неавторизованного запроса и защищённый
   `/api/publish?dry_run=true`: результат должен содержать `telegram_verified=true`.
5. Установить `JOURNAL_PUBLISH_ENABLED=true`, развернуть Production и проверить
   реальную отправку после 22:00 МСК. До этого времени функция не публикует.
6. Отключить плановые триггеры GitHub Actions после подтверждения замены, оставив
   возможность ручной диагностики.

Оба издателя используют один файл состояния в GitHub и проверку SHA при записи.
Даже при одновременном запуске только одна попытка сможет сохранить резервирование
до обращения к Telegram. Неопределённая отправка оставляет `pending` и требует
проверки канала перед повтором. Изменение очереди рубрик происходит после успеха.
Прогресс дневного блока хранится в `daily_batches` по московской дате. Повторный
запуск отправляет только оставшиеся материалы, до лимита 15.

Проверки локально: установить `requirements.txt`, затем
`python -m unittest discover -s cloud -p 'test_*.py'`.
