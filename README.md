# L’ART DE VIVRE

Telegram-журнал: @lartdevivre_journal.

## Облачная публикация

Режим: ежедневный блок из 100 публикаций в 22:30 по Москве (19:30 UTC),
15 материалов по каждой из пяти основных рубрик, 10 о книгах/кино и 15 викторин.
Все семь направлений чередуются в течение блока.
Публикация работает через GitHub Actions. Vercel не используется.
Компьютер и Codex не нужны.
Если плановый запуск приходит после полуночи, он продолжает последний выпуск
по его московской дате. Подтверждённые материалы повторно не отправляются.
GitHub может задерживать плановые запуски: это расписание, а не гарантия отправки
минута в минуту. Прогресс блока сохраняется после каждого подтверждённого материала.
Повторный запуск продолжает блок до 100 и не отправляет подтверждённые посты повторно.
GitHub не гарантирует точность расписания: возможны многочасовые задержки.
Поиск музея использует `/v1.1/search`: прежний `/v1/search` отключён.

Токен хранится в GitHub Actions Secret `TELEGRAM_BOT_TOKEN`. Его нельзя помещать
в код, коммиты, журнал запуска или обычные переменные репозитория.

Пять рубрик идут по кругу: история моды → архитектура → культурные путешествия →
женщины в искусстве → картина дня. Указатель `next_rubric_index` продвигается только
после подтверждённой публикации. Неудачная попытка не меняет рубрику.
Из подготовленной очереди `cloud/queue` берётся новый материал нужной рубрики.
После исчерпания очереди программа сама находит новые открытые экспонаты через официальный API
Метрополитен-музея и составляет короткие музейные карточки на основе каталога.
Оригинальные названия и датировки сохраняются без выдуманного перевода. Платные
сервисы генерации не нужны. Изображения проверяются на Public Domain; URL источника
хранится в состоянии, но не показывается в подписи. Принадлежность к рубрике
проверяется по музейным полям: одежда — Институт костюма, художницы — поле автора,
архитектура — сооружения, элементы, проекты и мебель, путешествия — исторические виды мест.
Книги/кино — литературные и театральные сюжеты с проверяемой связью, викторины —
нативные опросы с фото и ответами из каталога. При автоматическом подборе современные
афиши, тренды и маршруты не выдумываются. Фото одной серии не заполняют весь выпуск:
не более одной цианотипии и двух работ одного автора в последних 100 материалах;
один автор не повторяется подряд. Повторные изображения и работы отбрасываются.
Издатель меняет приоритет поиска от недели к неделе. При составлении подписей
и викторин он предпочитает ракурсы и форматы, которые реже встречались недавно.
Вопрос о конкретной технике появляется, только если в каталоге она указана однозначно.
Подбор учитывает недавние сюжеты внутри рубрик, например города в путешествиях
и виды работ в рубрике о художницах. Для каждой рубрики используется список
кандидатов из открытого каталога Метрополитен-музея с проверкой каждого объекта
через официальный API. Пробный запуск собирает по три разных материала на рубрику.
Редакторские карточки могут содержать проверенный ответ официального API и дату
проверки фото. Снимок принимается до семи дней с проверкой ID, лицензии, изображения
и контрольной суммы; затем требуется новый запрос каталога. `dry_run` проверяет
наличие материала каждого направления и права бота без отправки постов.

`cloud/state.json` хранит использованные экспонаты, подтверждённые сообщения и
незавершённую попытку. Сначала программа сохраняет резервирование в GitHub, потом
отправляет в Telegram и сохраняет квитанцию. Если ответ потерян, следующая отправка
блокируется до ручной проверки канала. Это предотвращает дубли. Коммиты состояния
также поддерживают активность репозитория для планового запуска GitHub.

В разделе Actions можно выполнить ручную проверку с `dry_run=true`. Она проверяет
источник и подпись без публикации. Для остановки достаточно отключить workflow.
Ошибки видны в Actions; никакого отдельного платного сервера не требуется.

## Локальная работа

Редакционные предпочтения: `EDITORIAL.md`. Локальные отправки:
`scripts/Publish-VisualPost.ps1 -PostPath content/имя.json`.
`main.go` — старый тестовый отправитель; его запуск отправляет тестовое сообщение.

Проверки облачного кода: `python -m unittest discover -s cloud -p 'test_*.py'`.

## Разовая публикация подготовленных 100 материалов

`python scripts/publish_collection.py prepare` собирает локальный план для конкретного
пакета LDV-001—LDV-100: 85 коротких статей и 15 интерактивных викторин. Изображения
берутся из официальных каталогов Met и Art Institute of Chicago с отметками
Public Domain/CC0; музейные иллюстрации подписываются отдельно. URL остаются
только в локальном плане. Этот пакет не заменяет ежедневную очередь.

`python scripts/publish_collection.py publish` отправляет пакет в канал без
звуковых уведомлений. Скрипт использует Telegram из локального `.env` и сохранённый
в Git Credential Manager доступ к GitHub. Состояние `editorial_batches` и
резервирование в `cloud/state.json` позволяют продолжить подтверждённый пакет без
повторов. Успешный ответ сначала сохраняется в локальный `delivery-journal.jsonl`,
затем в GitHub. При неизвестном результате отправка останавливается. Фото обязательно:
при недоступном изображении отправка останавливается до его замены; отправка одним
текстом запрещена. Сводные квитанции — в materials/imported/mass-receipts.json.

`scripts/repair_collection_photos.py` подбирает свободно лицензированные фотографии
и добавляет их к существующим статьям через `editMessageMedia`, сохраняя адреса
публикаций. Кандидаты требуют редакторского выбора в локальном photo-selections.json.
Авторство и лицензия указываются в подписи, адрес источника сохраняется в квитанции.
