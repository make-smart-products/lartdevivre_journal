# L’ART DE VIVRE

Telegram-журнал: @lartdevivre_journal.

## Облачная публикация

GitHub Actions запускает `cloud/publish.py` каждый час круглосуточно.
Компьютер и Codex не нужны.
GitHub может задерживать плановые запуски: это расписание, а не гарантия отправки
минута в минуту. Дополнительно выполняются резервные проверки в :07, :27 и :47
каждого часа: они подхватывают пропущенный запуск. Состояние разрешает только одну
публикацию на часовой интервал; пропущенные интервалы не заполняются пачкой.
GitHub не гарантирует точность расписания: возможны многочасовые задержки.
Поиск музея использует `/v1.1/search`: прежний `/v1/search` отключён.

Токен хранится в GitHub Actions Secret `TELEGRAM_BOT_TOKEN`. Его нельзя помещать
в код, коммиты, журнал запуска или обычные переменные репозитория.

Пять рубрик идут по кругу: история моды → архитектура → культурные путешествия →
женщины в искусстве → картина дня. Указатель `next_rubric_index` продвигается только
после подтверждённой публикации. Неудачная попытка не меняет рубрику.
Из подготовленной очереди `cloud/queue` берётся новый материал нужной рубрики.
После исчерпания очереди программа сама находит новые открытые экспонаты через официальный API
Метрополитен-музея и составляет короткие музейные карточки на основе каталога.
Оригинальные названия и датировки сохраняются без выдуманного перевода. Платные
сервисы генерации не нужны. Изображения проверяются на Public Domain; URL источника
хранится в состоянии, но не показывается в подписи. Принадлежность к рубрике
проверяется по музейным полям: одежда — Институт костюма, художницы — поле автора,
архитектура — сооружения, элементы и проекты, путешествия — исторические виды мест.

`cloud/state.json` хранит использованные экспонаты, подтверждённые сообщения и
незавершённую попытку. Сначала программа сохраняет резервирование в GitHub, потом
отправляет в Telegram и сохраняет квитанцию. Если ответ потерян, следующая отправка
блокируется до ручной проверки канала. Это предотвращает дубли. Коммиты состояния
также поддерживают активность репозитория для планового запуска GitHub.

В разделе Actions можно выполнить ручную проверку с `dry_run=true`. Она проверяет
источник и подпись без публикации. Для остановки достаточно отключить workflow.
Ошибки видны в Actions; никакого отдельного платного сервера не требуется.

## Локальная работа

Редакционные предпочтения: `EDITORIAL.md`. Локальные отправки:
`scripts/Publish-VisualPost.ps1 -PostPath content/имя.json`.
`main.go` — старый тестовый отправитель; его запуск отправляет тестовое сообщение.

Проверки облачного кода: `python -m unittest discover -s cloud -p 'test_*.py'`.
